# AI test: Hide Edge, caps and joins (part 4, step 3) with the `aia` CLI (2026-11-20)

**Setup.** An AI agent with only `node bin/aia.js …` (no repo files, no source) and the images `render` writes.
It learned the tool from `aia help`, `aia help <command>` (edge, fill, shape) and `aia guide` (start, points, ops,
paths, path).

**Task.** A new document `prueba_ai_edges`: a simple cartoon face (head outline, two eyes, a mouth line). Make the
head's skin with Create Shape (`aia fill` / `aia shape`) with both a fill and a stroke, hide a piece of the shape's
stroke (the chin) without touching the fill, and hide one side of an element's own stroke. Give the mouth butt caps
and the head a miter join. Rename the head, check the hidden stretches hold, show one stretch again, render.

**Result: done, about 50 commands (of them 8 renders), 11 refused (all on purpose, to probe errors), 3 silent
surprises.** Layer `face`: `head` (8-point ellipse line, named top, tr, right, br, chin, bl, left, tl, no fill),
`eye_l`/`eye_r` (4-point ellipses, white), `mouth` (open 3-point line via `ops create`). `aia fill face --at 400,180
--fill … --stroke … --stroke-width 8 --stroke-join miter` made `head_fill` + `head_stroke`, with the eyes found as
2 holes. `aia edge head_stroke head.bl head.chin --hide` and `head.chin head.br --hide` hid the shape's stroke at the
chin; the fill stayed (render checked). Since the `head` line draws its own stroke on top, the chin only became
"fill only" after hiding the same two stretches on `head` as well. `aia edge eye_r eye_r.0 eye_r.1 --hide` hid a
quarter of an eye's own stroke (the brown shape stroke around the hole then showed under it; hiding that hole stretch
on `head_stroke` too worked). Caps/joins: `ops set mouth strokeCap butt` and `head strokeJoin miter`; the miter was
only visible after making `head.top` a corner and pulling it up (`aia corner`, `aia move`). `ops rename head → skull`
renamed `skull_fill`/`skull_stroke` and rewrote every `hiddenEdges` pair (`skull.chin`…); renaming `eye_r` too.
`aia edge skull_stroke skull.br skull.chin --show` drew that stretch again (render: the brown shape stroke reappeared
from the chin to br, the line's own stroke still hidden there). `export --format svg` carried `butt` and `miter`.
Document deleted at the end.

## What went wrong or was hard

| What | Why |
| --- | --- |
| **"Only the fill shows at the chin" takes four commands, and the guide does not say so** | A shape made by `fill`/`shape` sits *under* its line, and the line has its own stroke. Hiding the chin on `head_stroke` alone changed nothing visible except the thickness (the line's 4 px stroke still ran over it). I had to also hide `head`'s own stroke on the same stretches. The help example `aia edge face head_stroke head.2 head.3 --hide` suggests this is enough. A sentence such as "the line it follows draws its own stroke over it: hide it there too, or give the line no stroke" would help. |
| **`edge` with three points silently uses two** | `aia edge doc skull skull.left skull.bl skull.chin --hide` hid `bl–left` and ignored `skull.chin` without a word. It should refuse ("give exactly two points"), or hide each stretch of the run (that would also solve the row above). |
| **Hiding on a part with no stroke is accepted silently** | `aia edge doc head_fill head.top head.tr --hide` answered "Hid the stroke of head_fill…" and stored a pair on a fill-only part, which does nothing. `--show` on the same pair *did* warn ("head_fill has no stroke, so nothing shows there yet"); `--hide` should warn the same, or point to `head_stroke`. |
| **`add-point` drops hidden edges without telling** | `aia add-point doc skull --at 330,500` between bl and chin dropped `["skull.chin","skull.bl"]` from both `skull` and `skull_stroke`; the answer only said "Added skull.jaw_l … (vertex 5; …)". Documented in the guide ("a point added between them … is dropped"), but the command's answer should say "un-hid skull.bl–skull.chin on skull, skull_stroke". `undo` restored it. |
| Auto point names do not match indices | The eye points were named by the fill: index 0 → `eye_r_1`, index 2 → `eye_r_2`; then `edge` named index 1 `eye_r_3` and `eye_l.3` became `eye_l_3`. So `eye_r.1` is `eye_r_3` and `eye_r.2` is `eye_r_2`. Workable (the answer says "named now: …") but confusing when reading `hiddenEdges` later. |
| No command to change cap/join of an existing part | `--stroke-cap`/`--stroke-join` exist only on `rect`, `ellipse`, `shape`, `fill`. For the mouth (made with `ops create`) and to restyle the line `head`, a raw `ops set` was needed. Easy with `aia guide path`, but a style command by id would be natural. |
| Miter join is invisible on a smooth outline | The head is an ellipse with curve handles everywhere, so `strokeJoin: miter` changed nothing in the render until I made a corner. Not a bug; the help could say joins only show at corners. |
| Shape stroke also runs around the holes | `head_stroke` outlines both eyes (holes). Expected from the last test, but it means hiding one side of an eye's own stroke shows the shape stroke under it; to really open the eye you hide two parts again. |
| The answer to `rename` reads like delete + create | "created: skull_fill, skull_stroke, skull; gone: head_fill, head_stroke, head." The hidden edges were kept, but the wording made me check with `show` first. History entries for `rename` and raw `set` batches have no note. |
| `edge doc face …` says `there is no part "face"` | `face` is a layer; "face is a layer, name a part in it" would be clearer. |

Refusals, all clear about what to do: points not next to each other ("they must be next to each other along its
stroke (for a shape, points of the line it follows)"; also for the two ends of an open line and for a hole point with
a line point), unknown point (lists the named points), already hidden / already shown, missing or both `--hide
--show` ("Say one of --hide or --show"), a bad `strokeCap` value ("must be one of: round, square, butt").

What worked well: one stretch per command, by name; points without names got one automatically and the answer said
so; shape strokes take the line's points, holes included; rename (of the line and of an eye) rewrote every pair;
`--show` brought exactly one stretch back; `undo` restored dropped pairs; render shows caps at the opened ends; export
SVG keeps caps and joins.

## Parity with the editor (Hide Edge, caps, joins)

| Editor action | By command? | How / how hard |
| --- | --- | --- |
| Hide Edge (H): click a stretch to hide it | Yes | `aia edge <doc> <part> <p1> <p2> --hide`. Easy once you know the point names (`render --labels`). |
| Hide Edge: click a hidden stretch to show it | Yes | `--show`. Easy. There is no way to list the hidden stretches except reading `hiddenEdges` in `aia show`. |
| Hide Edge with Alt: the stroke under the topmost | Yes, better | The CLI names the part directly (`head_stroke` vs `head`), so there is no "topmost" problem. But nothing tells you that two strokes lie on the same stretch. |
| Hide several stretches in a row (several clicks) | Partly | One command per stretch; extra points are silently ignored (see above). |
| Inspector: stroke cap / join | Yes | At creation `--stroke-cap`/`--stroke-join` on rect, ellipse, fill, shape; afterwards only `ops set` with `strokeCap`/`strokeJoin`. |
| Undo a hide | Yes | `aia undo`. Each edge is its own step with a note ("Hide an edge of head_stroke"). |

## Higher-level commands I would have wanted (most useful first)

1. `aia edge` over a run of points (`edge doc head head.bl head.chin head.br --hide` hides both stretches) and a
   `--with-line` (or `--all`) flag that hides the same stretch on the line and every shape stroke that follows it,
   so "only the fill shows here" is one command.
2. `aia edges <doc> [part]`: list the hidden stretches, and which parts draw a stroke along a given stretch.
3. Warnings in answers: `edge --hide` on a part with no stroke, and `add-point`/`delete-point` saying which hidden
   edges they dropped.
4. `aia style <doc> <part>... [--stroke-cap …] [--stroke-join …] [--fill …] [--stroke …]` to restyle by id.
5. Auto names that follow the index (`eye_r.p0` … or `eye_r_0` for index 0), so names and indices do not cross.
